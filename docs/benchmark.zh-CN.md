# RRBench：评测"做讲解视频的 AI"的基准

**状态：设计稿（v0.1）。** 现在的 `reels bench`（8 个题目，一个评审分）是它的种子。English: [benchmark.md](benchmark.md)。

RRBench 只回答一个问题：**给一个题目或一道题，AI 系统能不能做出一部内容正确、真能教会人、而且做得好的短片？它会不会越做越好？**

## 1. 为什么要做一个新的

| 现有基准 | 衡量什么 | 用在讲解视频上缺什么 |
|---|---|---|
| [VBench / VBench-2.0](https://vchitect.github.io/VBench-2.0-project/) | 生成视频的画质、物理和常识是否合理（5 大类、18 个维度） | 画面再好看，也可能讲错；没有旁白，也不检查论证对不对 |
| [TheoremExplainBench](https://tiger-ai-lab.github.io/TheoremExplainAgent/) | 240 个定理，用 Manim 做讲解，LLM 按 5 个维度打分 | 完全由模型打分，没有任何东西经过客观验证 |
| [Code2Video / MMMC](https://github.com/showlab/Code2Video) | 456 个 3Blue1Brown 风格的题目；**TeachQuiz**：让模型"忘掉"一个知识点，看完视频后能不能重新学会 | 思路很好，但只有一种风格、只有英文、没有结果检查 |
| [Paper2Video](https://showlab.github.io/Paper2Video/) | 论文 → 报告视频；**PresentArena**（和真人报告两两比较）、**PresentQuiz** | 做的是幻灯片加数字人，不是讲解动画 |
| [Teaching Monster 挑战赛](https://arxiv.org/html/2608.08852) | 按学习者画像做教学视频；LLM 初筛 → 众包两两盲比 → 专家评审 | 关键发现：LLM 评审能筛掉差的作品，但给顶尖作品排名时和人类评判**几乎不相关（ρ = −0.17）**；约每 6 个视频就有 1 个含严重事实错误 |
| [Terminal-Bench](https://www.tbench.ai/) | 智能体在 Docker 里干活；任务 = 指令 + 环境 + **对最终状态的测试** + 参考解 + 时间限制；任何智能体框架都能来跑，榜单公开运行轨迹 | 正是我们想要的评测方式，只是任务不同 |
| [SWE-bench Verified](https://www.swebench.com/) / [DeepSWE](https://www.together.ai/blog/deepswe) | 跑测试判断问题是否真的解决；Pass@1 和"多次生成 + 验证器挑选"分开报告（DeepSWE：16 次里挑 1 次，从 42.2% 提到 59%）；训练环境（R2E-Gym）和测试集严格分开 | 正是我们想要的报告规范 |

目前没有任何基准用客观检查来验证讲解视频，也没有任何基准衡量"做视频的系统会不会从经验中进步"。RRBench 两样都做。

## 2. 设计原则（以及各自借鉴自哪里）

1. **只检查最终成品**（借鉴 Terminal-Bench）：只有对渲染出的 MP4 做的检查全部通过，任务才算完成。检查项包括：能播放、答案正确且出现在画面上、该讲的事实讲到了、没有出现已知的错误说法。不看智能体是怎么做出来的。
2. **不限定系统**：输入是任务指令（可附图片或参考视频），输出是 `/output/video.mp4`（可选附 `subtitles.srt` 和项目代码）。任何智能体、任何流水线，甚至直接生成像素的视频模型，都可以参加。Reels-RSI 只是参赛者之一，不当裁判。
3. **用测验衡量"教会了没有"**（借鉴 TeachQuiz、PresentQuiz）：每个任务配一套隐藏的选择题，由一个只能看到视频的"学生模型"作答。
4. **画面质量用盲比，多个评审，人类抽查**（借鉴 Teaching Monster、PresentArena、Chatbot Arena）：1–5 分的绝对打分在顶部会挤在一起拉不开。改成两两盲比，每对交换顺序评两次，评审来自至少两家模型厂商，结果折算成带置信区间的 Elo 分。每个版本抽一部分交给人类评，并公布评审与人类的一致程度。
5. **细分维度只用来诊断**（借鉴 VBench）：评分表的各个维度用来解释"为什么赢"，单独列出，不加进主分数。
6. **训练和测试分开；Pass@1 和多次挑选分开报告**（借鉴 SWE-bench、DeepSWE）：会自我改进的系统在训练池里学习，只在没见过的任务上测分。
7. **单设一个"自我改进"赛道**：第一个衡量"进步幅度"的视频基准，看系统从自己过去的片子里学到了多少。
8. **每一项检查本身也要被检验**：每个任务附一部必须通过的参考片，和几部必须失败的"变异片"。这和 Reels-RSI 规则的"正反样例"是同一个思路。

## 3. 一个任务长什么样

```
tasks/solve-chicken-rabbit/
├── task.toml        指令、类型、语言、画幅、时长范围、受众、输入材料
├── facts.toml       经过核实的事实：答案、必须讲到的内容、不许出现的错误说法、出处
├── tests/           对 /output 的结果检查（pytest）
├── quiz.jsonl       隐藏的 5–8 道选择题，给学生模型作答
├── oracle/          一部能通过全部检查的参考片（证明任务可完成、检查合理）
├── mutants/         必须失败的变异片：答案错、答案没上屏、出现错误说法、超长 40%
└── reference.mp4    可选：真人或已知最好的片子，作为盲比的基准
```

检查只读成品，不读项目代码：
- 用 `ffprobe` 查时长、音轨、分辨率；
- 用语音识别拿到逐字时间，再把中文数字统一转成阿拉伯数字（三十五 → 35）后做匹配；
- 用视觉模型**抄写**画面上的文字，由代码判断答案是否出现；
- 检查画面有没有长时间冻结或黑屏。

## 4. 题库构成

v1 目标是 **240 个任务**：
- 120 个测试题；
- 60 个训练题，供会自我改进的系统使用；
- 60 个私有验证题，每个版本更换一批，防止题目泄露后被针对性训练。

| 类别 | 占比 | 难在哪 | 可以客观验证的部分 |
|---|---|---|---|
| 解题：数学、物理、化学（小学 → 高中） | 35% | 多步推理、几何图形、竖屏板书 | 答案、步骤、验算 |
| 拍照出题 | 10% | 看懂真实的课本照片，按题目给的长度画图，而不是照着照片比例描 | 题目转写 + 答案 |
| 科普原理 | 20% | 要让原理"动起来"，而不只是贴标签；3D、模拟 | 必须讲到的因果关系、不出现错误说法 |
| 历史地理 | 15% | 地图、年代、事件顺序、当时的地理 | 年代、事件顺序、地图上的地点 |
| 语文与语言（古诗、笔顺、英语） | 10% | 准确和意境要兼顾 | 原文准确、笔顺正确、读音正确 |
| 风格模仿（"照这个视频的风格做"） | 5% | 学参考视频的节奏和配色，但不照抄内容 | 平均镜头时长、配色距离 |
| 长片（3–5 分钟，分章节） | 5% | 多个镜头之间保持连贯 | 章节结构、前后呼应 |

每个类别都覆盖不同语言（中文 50%、英文 30%、中英双语 20%）、两种画幅（16:9、9:16），以及三档难度：
- 简单：30 秒讲一个点；
- 中等：60–90 秒，多个步骤；
- 困难：拍照出题、双语或长片。

## 5. 怎么算分

**第一层 · 硬性检查 → 完成率（主指标）。** 全部检查通过才算完成这个任务，检查项有：
- 能渲染出来，时长在范围内，有声音；
- 答案正确，并且出现在画面上；
- 该讲的事实都讲到了，没有出现禁止的说法；
- 没有内容被裁掉或压到字幕区；
- 没有超过 3 秒的黑屏或冻结。

报告 Pass@1（只做一次）和 Pass@k（做 k 次至少成功一次）。

**第二层 · ReelQuiz → 学习增益。** 固定的学生模型答两次隐藏测验：一次不看视频，一次只看视频（画面 + 旁白文字）。增益 = 看后正确率 − 看前正确率。大模型本来就会做小学题，所以：
- 学生模型故意选小模型，每个版本固定不变；
- 题目侧重"这部片子讲的方法和步骤"（比如"片子先假设了什么？"），以及换了数字的迁移题；
- 公布"不看视频"的基线正确率，这样测验一旦失效（不看也能答对），大家都看得到。

**第三层 · 盲比 → 画面质量 Elo。** 同一任务下，不同系统的片子（以及参考片）两两盲比：
- 评审团由至少两家厂商的视觉模型组成，每对交换顺序各评一次；
- 用 Bradley–Terry 模型折算成 Elo，附 90% 置信区间；
- 每个版本抽约 10% 的对比交给人类评审（解题类请老师，科普和历史请普通观众）；
- 榜单公布评审与人类的一致程度，低于阈值就给这一列加警示标记。

**第四层 · 诊断信息（列出，不参与排名）。**
- 评分表的 6 个维度：主体丰富度、原理演示、镜头与引导视线、节奏、构图、一致性；
- 程序检查结果：规则违规、音画同步误差、字幕区违规；
- 成本：耗时、token 数、费用、合成检查的轮数。

**榜单列：** 系统（智能体 + 模型）· 完成率@1 · Pass@3 · 学习增益 · 画面 Elo（置信区间）· 每部片子的费用 · 每部片子的耗时。

另设 **多次挑选赛道**：允许生成 n 次，由系统自己的验证器挑出一部（参照 DeepSWE 的做法）。这个成绩单独列，不和 Pass@1 混在一起。

## 6. 自我改进赛道（RSI）

这是现有视频基准都没问过的问题：**系统能不能自己变好？**

1. **之前**：记忆清空，做 60 个测试题 → 记下完成率₀ 和 Elo₀。
2. **积累经验**：按固定顺序做 60 个训练题，学到什么都可以留下来（经验、规则、改写技能、微调模型，方式自选）。只能看到训练题的检查结果和评审意见；人工把关要么关掉，要么记作"人工干预"。
3. **之后**：再做同样的 60 个测试题 → 完成率₁ 和 Elo₁（新旧片子直接两两盲比）。
4. **对照组**：同样流程再跑一遍，但关掉学习，用来扣除每次运行本身的随机波动。
5. **遗忘检查**：最后重做 10 个早期的训练题，确保进步不是靠"忘掉旧本事"换来的。

报告：**完成率提升**、**Elo 提升**（都带置信区间），积累经验阶段的成本，人工干预次数，以及 60 个训练题上的学习曲线。

## 7. 可信度保障

- **任务经过验证**：参考片必须通过、每部变异片必须失败，并由两位审核人确认事实和出处。如果有人能用一部错误的片子骗过检查，这个任务就修改或删掉。
- **防泄露**：测验题、变异片和私有验证集只放在评测服务器上；公开的任务文件里埋入"金丝雀"标记字符串，一旦被拿去训练能查出来；私有验证集每个版本更换。
- **防作弊**：检查只读最终的 MP4；评审看不到系统名字；评审模型每个版本轮换；任务禁止写入 `/tests` 目录。
- **可复现**：Docker 镜像固定版本（Chrome、FFmpeg、字体、Node），配音结果缓存，固定随机种子；每次运行公开完整轨迹和项目文件夹，和 Terminal-Bench 一样。
- **安全**：智能体在一次性容器里运行，网络只开放声明过的服务（配音、模型 API、维基共享资源、Natural Earth 地图数据）。

## 8. 从现在的 `reels bench` 到 RRBench

| 现在 | RRBench |
|---|---|
| `topics.toml` 里 8 个题目 | 240 个任务文件夹 |
| 综合分 = 0.6 评审分 + 0.4 程序检查分 | 硬性检查 → 完成率；测验 → 学习增益；盲比 → Elo；评分表只作诊断 |
| 一个评审模型 | 评审团 + 人类抽查 + 一致性报告 |
| `evolve` 用训练集/验证集 | 自我改进赛道，对任何系统开放 |
| 只能评 Reels-RSI | 任何系统都能按输出约定参加 |

路线图：
- **v0.1**：把现有 8 个题目改成任务格式，给其中 4 个解题和科普题写好检查和测验，用 Reels-RSI 搭配两个模型跑一遍。
- **v0.2**：60 个任务，上线评审团，做第一次人类抽查。
- **v1.0**：240 个任务，公开榜单，开放自我改进赛道和外部提交。

## 9. 还没想清楚的问题

- **小模型当学生靠不靠谱？** 学习增益用小模型当学生，和真人学生的结果是否一致，需要做一次小规模真人实验。Code2Video 发现画面美感和学习效果高度相关（r = 0.97），值得在中文 K-12 题上再验证。
- **配音的可复现性。** 免费的 Edge 配音是非官方接口，评测环境需要一个有授权的或本地的备用方案。
- **类别权重。** 主分数要不要按类别平均，避免解题类占比太高、主导排名？

## 10. 一个完整的样例，以及它已经教会我们的

[`benchmark/example-task/`](benchmark/example-task/) 是一个完整的任务（鸡兔同笼，16:9，30 秒），包括 `task.toml`、`facts.toml`、隐藏式的 `quiz.jsonl`、13 项结果检查，以及生成变异片的 `make_mutants.py`。把它跑在第一轮 evolve 为这道题做的两部片子上：

| 片子 | 通过的检查 | 是否完成 |
|---|---|---|
| 旧版技能做的 | 12 / 13：最后四分之一的画面没有写出"兔 12"（12 只出现在 `23×2+12×4` 里） | ✗ |
| 进化后技能做的 | 13 / 13：结尾写明"鸡 23 兔 12"并验算 | ✓ |
| 变异片：说错答案 | 被 3 项检查拦下 | ✗ |
| 变异片：列方程 | 被拦下（`forbidden.equation`） | ✗ |
| 变异片：后 40% 冻结、答案不出现 | 被 2 项检查拦下 | ✗ |
| 变异片：时长翻倍 | 被拦下（`length_window`） | ✗ |

做这个样例的过程中，设计改了三处：

1. **让模型抄写，由代码判断。** 问视觉模型"答案在不在画面上？"，同一个边界画面它一次说在、一次说不在。让它把画面上的文字抄下来就很稳定，而且判断规则写在代码里，任何人都能对照它抄下来的文字复查。
2. **变异片能找出检查本身的漏洞。** 第一版的冻结检查放过了"最后 40% 冻结"（ffmpeg 对冻结到结尾的情况不报告时长）；"说错答案"的匹配规则漏掉了"兔就是十三只"这种说法。两个漏洞都是因为"变异片必须失败"这条要求才被发现的。
3. **这道题上，硬性检查和盲比的结论一致**：盲比评审更喜欢的那部片子，也是唯一完成任务的那部。但两者衡量的东西不同，所以都要报告。
